# 人力与自动化图谱：完整替换计划

本版替换旧方案，明确两项要求：

1. **最新官方数据决定主视图和行业筛选，2023 年资料仅用于必要的细分分析。**
2. **全站支持任意区域框选、就地评论和回复，不设置固定评论区。**

## 1. 研究范围与行业筛选

中国、美国分别研究、分别呈现，各选增加值 Top 10。若未覆盖第一、二或三产业，在榜单之外补充该缺失产业内增加值最高的可识别行业。

**数据采用“最新全年＋近五年趋势＋最新一期”的结构：**

- 主榜优先采用最新已发布的完整年度官方现价增加值，当前以 2025 年为首选；执行开始和发布前再次检查更新。
- 收集 2021—2025 年可获得的历史数据，同时展示已发布的 2026 年季度、半年或月度进展。
- 中国按照已确认的“最新官方大类优先”原则筛选，再向下拆解子行业和具体任务。2023 年投入产出表作为详细结构资料，不作为默认主榜。
- 美国使用 BEA 最新年度行业增加值与历史序列，最新季度以行业明细的实际发布时间为准。
- “其他行业”保留为未拆分汇总，显示其规模及覆盖缺口，不编造拆分结果；具名行业榜明确标注统计范围。
- 同一榜单使用相同统计期和非重叠分类，不混列父子行业，不混用增加值、营业收入、实际增速与季度年化值。
- 每项数据显示数据期、发布日期、修订状态、单位、覆盖范围和来源。历史序列使用最新修订值，缺失值留空。

网站首页首先呈现最新情况，用户可以切换年份查看变化。较老的数据必须在使用位置明确标注，不能仅在脚注中说明。

## 2. 从行业到全部人工任务

聚焦实体劳动，比较传统机械、专机、机器人、辅助工具及必要的数字流程。按可独立描述、验收和核算的任务研究，不用岗位名称代替任务分析。

每个入选行业完成以下流程：

1. 拆解主要子行业和场景，绘制作业、交接、检测、异常处理、返工、清洁维护与交付流程。
2. 从流程规范和职业职责两条路径收集人工任务，交叉检查遗漏与重复。
3. 对所有识别出的任务逐项调查，不限制为每行业几个案例。
4. 查找现有自动化方案及成功条件，同时检索失败、退出或未采用的证据。
5. 独立复核来源与结论，冻结首版任务清单。

每项任务必须记录：执行条件、人工投入、替代方案、部署阶段、残留人工、技术障碍、经济障碍、采用障碍、成功反例、证据缺口和待访谈问题。

**证据与计算要求：**

- 每个数字和实质结论绑定来源及原文定位，区分直接事实、计算结果、研究判断和待验证假设。
- 厂商自报、实验室结果、试点与持续商业运行分别标记。
- 查不到案例不能证明技术不可行；职业任务描述不能证明工时或人工占比。
- 第 2／3 类判断必须附具体场景，允许多种障碍同时存在。
- 回报按增量现金流计算，包含完整部署投入、残留人工、维护、异常和停机；增产收益须有需求与瓶颈依据。
- 参数不足时显示缺口或有明确假设的盈亏门槛，不生成虚假回收期。
- 每国独立形成机会清单，解释值得深入的原因、成立条件及下一步验证方法。

首版基于公开资料交付，所有任务均须有研究结果或明确的证据不足说明；一手访谈形成后续工作清单。

## 3. 图谱与任意区域批注

网站阅读路径为：

**国家 → 最新行业全景 → 行业流程 → 具体任务 → 证据与回报**

采用白底、深色文字、蓝色强调。国家页展示最新规模和趋势；行业页展示流程与任务；任务页先呈现结论和条件，详细证据按需展开。数字、结论和图表均可追溯、分享和导出。

**批注直接发生在内容上：**

- 选中文字后浮出“添加批注”按钮。
- 开启批注模式后，可对正文、表格、图表、图片、空白或跨组件区域拖出矩形，并调整选区。
- 选区旁出现浮动编辑卡；输入首条评论即可提交，自动生成议题标题。
- 提交后在原位置留下标记；点击标记就地展开评论、回复和处理记录。
- 每条评论均可回复；回复另一条回复时显示被回复对象，保持两层视觉结构。
- 标记和浮动卡直接显示 Open／Closed；关闭、重开都在站内完成，关闭须选择原因并填写说明。
- 支持隐藏标记，以及筛选未关闭、已关闭、本人参与的批注；重叠标记聚合展示。
- 手机使用可调整的框选区域和底部浮层；键盘用户可以聚焦内容块添加批注。
- 不设置页尾评论区、“讨论与验证”内容区或独立讨论页面。

**选区必须能稳定恢复：**

每条批注保存页面、研究版本、稳定内容编号、文字及上下文、相对选区位置、图表数据点、年份、筛选状态和选区快照。

文字换行、屏幕缩放、表格排序后依据内容重新定位；跨组件框选保存多个关联目标。原内容发生实质变化时提示“原内容已变更”，展示原始快照，不将批注错误挂载到新内容。

每条批注提供独立分享链接，打开后恢复页面状态并定位选区。快照仅包含用户选中的网站内容。

## 4. 实现与服务配置

项目名称为“人力与自动化图谱”，新建公开仓库 `JoenHune/labor-automation-atlas`。正文中文，保留必要英文术语。

- \*\*前台：\*\*VitePress、Vue、TypeScript、ECharts，通过 GitHub Actions 发布 GitHub Pages。
- \*\*后台：\*\*Cloudflare Workers；D1 保存会话、批注索引、缓存和去重记录；R2 保存选区快照。
- \*\*讨论：\*\*自建 GitHub App，每条区域批注对应一个 Issue，首评进入 Issue 正文，回复进入 Issue Comments。
- \*\*研究数据：\*\*统一保存行业时间序列、任务、结论、证据和研究版本，页面与图表从同一数据源生成。
- \*\*批注数据：\*\*增加选区目标、视图状态、版本、快照、Issue 编号和父评论编号。

后台接口覆盖登录、会话、按页面读取批注、创建批注、评论、回复、关闭／重开、快照上传和 Webhook。

GitHub 保存讨论正文和状态；选区及回复元数据同时写入可恢复的结构化标记。直接从 GitHub 发布的普通评论作为主评论展示。用户写入使用自己的 GitHub 授权，保留真实作者身份，操作权限遵循 GitHub。

登录使用 state、PKCE 和短期站点会话；GitHub 凭证仅保存在后台。实现权限检查、Webhook 验签、安全 Markdown 渲染、上传校验和提交去重。授权过期或网络失败保留草稿；状态无法刷新时显示更新时间。

**GitHub App 和 Cloudflare 配置由代理通过 Computer Use 完成。** 包括应用注册安装、Workers、D1、R2、回调、Webhook、密钥配置、部署及联调。先完成可运行代码和配置准备，再执行账号配置；遇到必须本人完成的身份验证或付费开通时，提出具体操作要求。

## 5. 阶段与验收

依次完成：最新数据底表与榜单 → 全流程任务清单 → 全任务证据研究 → 图谱与批注系统 → 服务配置、联调和公开发布。

先用两国各一个任务验证完整链路，再扩展全部范围，样板不替代最终交付。

必须通过以下验收：

- \*\*数据：\*\*主视图使用最新可得官方数据，近年趋势与最新一期已纳入；数据期、修订和覆盖缺口清楚可见。
- \*\*研究：\*\*全部任务完成检索与反例检查；所有公开数字和实质结论可追溯，计算可复算。
- \*\*国家隔离：\*\*排名、货币、任务、搜索、案例结论和批注关联不会串入另一国家。
- \*\*框选：\*\*文字、图表、图片、空白和跨组件区域均能就地批注，页面不存在固定评论区。
- \*\*定位：\*\*缩放、换行、排序、年份切换、内容更新和原文删除不会造成错误挂载。
- \*\*互动：\*\*真实 GitHub 身份下的新建、评论、回复、关闭、重开、权限拒绝及双向同步全部通过。
- \*\*异常：\*\*草稿保留、重复提交、父评论删除、快照失败、授权过期和服务不可用均得到正确处理。
- \*\*体验：\*\*桌面、平板、手机及文字放大后可用；标记可隐藏，分享链接可恢复上下文。

最终交付公开网址、完整研究数据、证据与方法说明、任意区域批注系统和待访谈清单。后续新证据通过批注进入审校与版本修订流程，评论不会自动变成研究事实。
